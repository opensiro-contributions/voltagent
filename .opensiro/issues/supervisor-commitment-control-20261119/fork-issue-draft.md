# VoltAgent — proposed composable S3 current-commitment control (OpenSiro roadmap)

**DRAFT ONLY — NOT PUBLISHED.** This is a proposed *public fork issue body* for opensiro-contributions/voltagent, distinct from any original-repository maintainer issue.

One installed VoltAgent application can compose a supervisor and specialist agents. This OpenSiro research proposal asks whether an optional first-party, developer-composed **current-team commitment manager** can make an independently chosen, parent-authorized admit/defer/reassign/hold decision over shared team resources *before specialist delegation* and receive the later result/usage. It does not request another tool guard.

**Accepted historical VSM (not current grades):** S1=A (Agent operations), S2=C (subagent coordination), S3=— (no observed team-wide current management), S3*=— (no proven separate audit owner), S4=— (no demonstrated future adaptation actor), S5=— (ultimate policy remains in application/parent). **Hypothesis:** S3=— -> S3=C at the multi-subagent application boundary. A manager installed by the developer would see versioned active commitments and lawful options, choose one under fixed application limits, enforce a reservation before child dispatch, then get linked success/error/usage feedback. It cannot override authorization or application policy. **Proposal verdict GO / research NEEDS_EVIDENCE**, native tests NOT_RUN, value/cost NOT_MEASURED, original maintainers' interest NOT_STATED.
